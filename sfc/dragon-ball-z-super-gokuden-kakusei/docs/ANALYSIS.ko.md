[English](ANALYSIS.md) | 한국어

  ED4 - F94      $98    $98:C1C8

   첫 바이트가 화자 번호입니다.

     넣고 $81:8000을 부릅니다. $81:8000은 8×8 타일 $020E칸 × $0210줄로
     창 타일맵을 깝니다.

## 2. v1.1의 진행 버그 원인 (우주선이 맵 밖을 헤매는 현상)

```text
v1.1에서 길어진 한글 크레딧·지명 문자열을 0xFF로 채워진 빈 공간에 넣었습니다.
그런데 두 곳 모두 실제 데이터가 끝나기 몇 바이트 전부터 덮어썼습니다.

 1) $83:F3AF (파일 0x1F3AF)
    컷신 캐릭터 X 좌표 테이블의 마지막 항목(0xFFFF)이 덮였습니다.
    이 테이블은 $83:E44F, $83:E755에서 읽습니다.
    결과: 캐릭터가 엉뚱한 좌표(x=0x2A5) 쪽으로 미끄러져 갑니다.

 2) $88:FFAE (파일 0x47FAE)
    $88:FFAA 이동 경로 레코드의 끝 표시(0xFFFF)와
    $88:FFB0 레코드 전체가 덮였습니다. (경로 포인터 테이블: $88:FC80)
    결과: 맵 이동 루틴이 지명 문자열 바이트를 경로로 읽어, 우주선이 맵 밖으로 나갑니다.

[실측] v1.1이 이 두 곳에 넣은 것은 대사 뱅크의 대사가 아니라
    $83:F3AF: 엔딩 크레딧 문자열 (포인터 $83:9009/900B/900D, $83:94AB/94C5)
    $88:FFAE: 지명 문자열 (포인터 $88:800C/8018/801C/8048)
입니다. 대사 8뱅크($98–$9F)의 한글 대사는 v1.1에서도 각 뱅크 안에 들어 있었습니다.

수정: 원본 바이트를 복구하고, 그 자리에 있던 문자열을 뒤로 밀고,
해당 문자열을 가리키는 포인터를 같은 만큼 고쳤습니다. (tools/fix_overwrites.py)
교훈: "0xFF가 이어진 곳 = 빈 공간"으로 보면 안 됩니다.
0xFFFF를 끝 표시로 쓰는 데이터가 바로 앞에 있을 수 있습니다.
빈 공간 앞뒤로 여유를 두고, 원본에서도 0xFF인지 확인해야 합니다.
```

## 3. 타이틀 화면

```text
 - 압축: LZSS, 해제 루틴 $80:9CFA
   · 앞 2바이트 = 풀었을 때 크기
   · 이후 플래그 바이트 1개 + 항목 8개씩 반복 (플래그는 하위 비트부터)
   · 플래그 1 = 리터럴 1바이트
   · 플래그 0 = 16비트 워드: 길이 = (워드 & 0xF) + 3, 거리 = 워드 >> 4
     거리가 출력 시작보다 앞을 가리키면 0으로 읽습니다.
   · $80:9DA7 변형은 해제 후 타일마다 플레인 순서를 재배열합니다.
     (플레인0 8줄 + 플레인1 8줄 → SFC 2bpp 순서)
 - 타이틀 BG3 자료 2개, 5바이트 항목(주소 하위, 주소 상위, 뱅크, 크기 하위, 크기 상위)으로 지정됩니다.
   · 2bpp 타일 (타일 0x000-0x134): $89:9B9D, 항목 위치 파일 0xD720
   · 32×32 타일맵: $89:C4F3, 항목 위치 파일 0xD95F
 - 다시 압축했을 때 원래보다 길어지면 파일 0x4C801-0x4FFFF(전부 0xFF) 영역으로 옮기고 항목을 고쳤습니다.
 - "DRAGON BALL Z" 로고와 "(c) BANDAI 1995"는 원본 그대로입니다.
   이 (c) 타일은 저작권 첫 줄과 같이 쓰므로 건드리면 안 됩니다.
 - 로고 아래 가타카나(ドラゴンボール) 줄은 빈 타일(0xFF, 타일맵에서 쓰지 않음)로 지웠습니다.
```

     글자판을 가리키게 했습니다($81:8B70, $81:8B82의 LDA long 피연산자).
   · A($81:89DD)는 조합, B($81:89E5)는 자모 하나 되돌리기(조합 중이 아니면 글자 하나 지우기),
     X($81:8A0B)는 빈칸, Y는 원래대로 모두 지우기, Start($81:89ED 뒤)는 커서를 「입력완료」로 옮깁니다(A로 다음 이름).
     일본판 Start는 이 화면에서 아무 일도 하지 않았습니다. 도움말($81:891A)도 「지우기」「띄어쓰기」로 바꿨습니다.
   · 조합 중인 음절은 $022B 칸에 있습니다. 다음 음절은 $022B + 1에 쓰고 그 이름의 남은 칸을 빈칸으로
     만듭니다. 이름 끝(다섯째 칸)을 넘는 키는 무시합니다. 커서가 B·입력완료·Y로 옮겨져 마지막으로
     쓴 칸과 코드가 달라지면 조합 상태를 버리고 그 칸부터 덮어씁니다. 그런 때의 B는 원래처럼 커서를
     한 칸 뒤로 옮기되, 그 이름의 끝 빈칸을 건너 마지막 글자 바로 뒤에 둡니다. Y($81:8A26)도 상태를 비웁니다.
   · 커서는 빈칸을 건너뜁니다: 원래 이동 코드의 끝 STA $0229 / JMP $89BA($81:8A58 오른쪽,
     $81:8A8D 왼쪽, $81:8AAF 아래, $81:8AD1 위)를 JMP로 바꿔, 빈칸이면 같은 방향 이동을 다시 돕니다.
   · 상태는 WRAM $7F:FF00-$7F:FF31. 부팅 뒤 새 게임·암호·전투 장면에서 아무도 쓰지 않은 곳입니다
     (CPU 주소 전체에 쓰기 콜백을 걸고 미러를 합쳐 확인). 화면을 열 때 $81:89A6에서 초기화합니다.
 - 타이틀 메뉴 가운데 정렬(tools/font16.py MENUS)
   · $84:A1D8(새 게임/옵션), $84:A1FA(이어하기/새 게임/옵션), $84:A22E(게임 시작/암호), $81:D654(이어서 할
     편 고르기: 피콜로편부터 등)는 앞 빈칸 수로만
     가운데에 놓여, 글자가 12px씩만 움직여 줄마다 최대 6px 어긋나고 「새 게임」 사이가 12px 빈칸이었습니다.
   · 커서 상자도 창 안쪽(x 66-189)에서 왼쪽 4px, 오른쪽 8px로 치우쳐 있었습니다(x 70-181). 상자의 x는
     $81:8672의 LDA #$0048 / STA $45라, 0x4A로 바꿔 72-183(양쪽 6px)으로 옮겼습니다.
   · 줄마다 대사 폰트 글자를 픽셀 단위로 늘어놓고(띄어쓰기 4px) 화면 x 128에 가운데를 맞춘 뒤 12px씩
     잘라 새 코드로 넣습니다. 줄의 코드 수는 그대로입니다. 결과: 네 메뉴 모든 줄의 글자 가운데가 x 128.
 - 두 음절을 한 칸에 눌러 그린 글자(tools/font16.py FIELDS)
   · 일본판이 한자 한 자를 쓰던 상태 화면 쪽 칸에 v1.1이 두 음절을 12px 한 칸에 그려 넣었습니다:
     0x273 전환, 0x274 취소, 0x275 험치, 0x276 다음. 쓰는 곳은 상태·달성치일람표·이벤트 클리어표·
     기술경험치·기술설정·기술습득표의 위 안내($84:86DC, 87E2, 886A, 888C, 8904, 896C)와 커맨드의
     「기술경험치」($84:878E)입니다.
   · 이 칸들은 정해진 코드 수만큼 복사되고($81:96AB 등의 LDX/CPX), 창 폭($020E)도 정해져 있어 늘릴 수
     없습니다. 대사 폰트 음절은 1px 간격으로 붙여도 들어가지 않아(예: 「기술경험치」 51px, 창 48px),
     버튼 아이콘은 그대로 두고 글자만 Galmuri11 Condensed(7px)로 칸 폭(코드 수 × 12px + 4px, 창 끝에서
     자름)에 맞춰 짜서 12px씩 새 코드로 잘랐습니다. 위 안내는 가운데, 커맨드 항목은 다른 항목과 같은
     자리에서 시작합니다.
   · 버튼 아이콘 색: 위 안내는 BG3(2bpp)이고, 화면마다 아이콘 자리의 타일맵 항목 4개(2타일 × 2줄)에 팔레트를
     ORA로 넣습니다($81:95F3 등의 LDA $7E5xxx / ORA #$0400·0800·0C00·1000 / STA $7E5xxx). 위 안내는 끝을 칸 끝(코드 수
     × 12px - 2)에 맞춰 오른쪽 정렬하고, 아이콘을 두 타일 안(왼쪽 x mod 8 ≤ 5)에 두고, 이 명령들의 주소를 새 타일로
     옮겼습니다. 새 글자는 아이콘 색을 지키려고 두 플레인을 그대로 담아(64바이트, 코드 0x3C00-, 뱅크 $CB) 렌더러가
     그대로 복사합니다. 커맨드 항목은 띄어 「기술 경험치」로 쓰고, 자간 2px·띄어쓰기 5px로 벌려 다른
     항목(기술설정·기술습득)과 끝(x 46)을 맞췄습니다.
 - 확인 (MesenCE 2.2.1)
   · 이름 다섯 개(뷁얅닭, 똠방, 쌤힣, 읊잖, 손오공)가 WRAM에 입력한 그대로 들어가고, 이름 목록,

   · B로 뷁 → 뷀 → 붸 → 부 → ㅂ → 빈칸, X 빈칸, 다섯 칸이 찬 뒤의 키 무시.
 - 에뮬레이터 호환성(compat/run_all.sh, 10장): v1.4 롬으로 new14(헤더 있음/없음), cont, bubble, narration,

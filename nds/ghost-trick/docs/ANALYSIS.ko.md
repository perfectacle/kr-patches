## 2. 스크립트(1LMG)

```text
■ 파일 구조 [확인]
0x34 바이트 헤더: '1LMG', 그 뒤 u32 들. +0x08 이 코드 구역 크기, +0x0C 가 이름 문자열 구역 크기.
코드 구역(u16 열) → 이름 문자열 → 레이블 표(u32 개수, (이름 위치, 파일 오프셋) 쌍) 순서다.

■ 대사 [확인]
대사는 FF2D 창 번호 … FFFE 블록이다. 앞뒤로 이어 붙은 대사들이 묶음(run)을 이루고,
묶음 사이에는 바이트코드와 FFFD … FFFE 이벤트 블록이 있다. 이벤트 블록은 제자리에 둔다.
대사 안 제어 코드(인수 개수):
  0개  01 줄바꿈, 02 다음 창, 03, 0F, 16, 17, 21, 23
  1개  05 글자색, 08 말하는 인물, 0C, 0D, 0E, 15, 19, 1B 말하는 인물, 1C, 1E, 20, 22, 24, 25, 2B, 2C, 2E
  2개  10, 27, 28, 2D(대사 머리)
  3개  1D
인수 개수는 일본판과 v1.1 의 같은 대사를 맞대어 정했다(tools/textcodec.py 의 ARGS).

■ 대사를 찾는 방법 [확인]
게임은 대사를 포인터로 찾는다. 포인터는 태그 u16 뒤의 u32 파일 오프셋이고, 태그는
37, 51, 4C, 40, 5D, DB, 5C, 45, 3C, 0, 1, 2, FFFD, FFF4, 228 이다(v1.1 이 일본판에서 고친 자리에서 모음).
레이블 표도 대사를 가리킬 수 있다. 첫 장면 두 대사의 번호(FF2D 인수)를 바꿔도 화면이 같았다.
system/database_0000 (수첩)만은 번호로 항목을 찾는다. 번호가 틀리면 그 항목이 나오지 않는다.

■ 다시 넣기 [확인]
v1.1 은 파일 크기와 이벤트 블록 위치를 그대로 두고, 묶음 안에서 대사를 이어 쓴 뒤 포인터를 고쳤다.
tools/lmg.py 의 repack 이 같은 규칙으로 넣는다: 묶음마다 새 대사를 이어 쓰고 남는 칸은 0 으로
채우며, 옮겨 간 대사를 가리키는 포인터와 레이블을 고친다. 묶음 크기를 넘으면 오류다.
일본판에 v1.1 대사를 넣으면 176개 가운데 170개 파일이 v1.1 과 바이트 단위로 같다(나머지 6개는 아래 v1.1 문제).

■ v1.1 대사 찾기 [확인]
v1.1 은 대부분 일본판 순서로 이어 썼지만, 번역하지 않은 대사를 제자리에 두거나 번호를 바꾸거나
남는 칸에 옛 대사 사본을 남긴 곳이 있다. tools/lmg.py 의 locate 는 대사마다
포인터로 찾은 위치 → 앞 대사 뒤 블록 → 같은 (창, 번호) → 같은 번호 → 앞 대사 뒤 첫 FF2D 순서로 찾는다.
tools/dump.py 로 뽑은 v1.1 본편 대사 3,503개를 다시 넣고 다시 뽑으면 대사와 머리가 모두 같다.
```

## 3. v1.1 에서 찾은 문제와 v1.2 의 처리

```text
■ 스크립트 [확인]
 - 대사 중간에 FFFE 가 들어가 뒷부분이 나오지 않는 대사, FFFE 뒤에 공백이 붙은 대사가 있다.
   v1.2 는 대사를 처음부터 다시 쓰므로 사라진다.
 - 레이블 표를 1 바이트 어긋나게 쓴 파일 2개: st07_game004, st15_demo060. 일본판에서 다시 만들어 바로잡힌다.
 - FF2D 의 창·번호를 바꾼 대사 28개. v1.2 는 일본판 값을 쓴다.
 - 수첩(database) 번호가 틀려 나오지 않던 항목: 268 「운명에 사로잡힌 사람」, 512 「과거 카논의 집」.
 - 일본어가 그대로 남거나 깨진 대사(예: st01_demo101, st06 27-4).

   되돌리는 {05:f} 가 빠진 곳.
 - 화자 코드가 빠지거나 뒤바뀐 대사, 수첩 이름 링크 코드 {29}…{2A} 가 빠진 대사.
 - 원문에 없는 역자 장난 대사 1개(st14).

■ v1.2 대본
v1.1 대사 4,048개를 일본판과 모두 맞대어 검수했다(오역, 빠진 문장, 맞춤법, 용어 통일, 줄 맞춤).
인물·지명 표기는 v1.1 을 따른다.
```

이미지 헤더(u32 ×9): 고정값, 이미지 개수?, ?, 헤더 크기, 이미지 크기, 팔레트 오프셋, ?, 가로, 세로.

## 7. 소리

```text
■ 패치 페이지 배경 음악 [확인]
sound_data.sdat(15,257,056 바이트, v1.1·v1.2 에서도 같음)의 시퀀스 37번 SEQ_GHOST_BGM054_B.
뱅크 534, 파형 묶음 1. 모든 트랙이 도입 4,608틱 뒤 3,072틱을 반복한다. 템포 70.
명령은 음표·쉼표·프로그램·C0(팬)·C1(트랙 음량)·C7(0)·CA(0)·E1(템포) 뿐이다.
악기 종류는 PCM(1), 드럼 세트(0x10), 키 분할(0x11). 파형은 IMA-ADPCM.
시퀀서·엔벨로프 갱신은 ARM7 33,513,982Hz ÷ (64 × 2,728) ≈ 191.96Hz.

desmume 녹음은 반복 회차마다 채널 배정이 달라 소리가 조금씩 달랐고, 녹음에서 상관으로 잡은
반복 길이(55.51초)도 실제(54.87초)와 달랐다. tools/sseq_render.py 로 합성하면 반복 2회차와
3회차가 표본 단위로 같다. 48kHz 에서 loopStart 83.590563초, loopEnd 138.460271초.

■ 녹음용 시험 롬 [확인]
tools/bgm_dump.py 는 SDAT INFO 의 SEQ 레코드(10 바이트)를 모두 곡 K 의 것으로 바꿔 어느 곡을 틀든
곡 K 가 나오게 한다. --quiet 는 SSAR 파일마다 레코드(12 바이트, 파일 +0x20 부터, 개수는 +0x1C)의
+6 음량 바이트를 0 으로 만들어 효과음을 끈다.
```
